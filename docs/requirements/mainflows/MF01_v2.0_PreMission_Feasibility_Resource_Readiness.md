## 2. Architecture Review / Decision

### 2.1. Kết luận kiến trúc

MF01 **không tạo `InspectionMission`**.

MF01 tạo một **planning/readiness aggregate** là `PreMissionAssessment` để trả lời câu hỏi:

> Với phạm vi kiểm tra và khung thời gian dự kiến này, site có khả thi không, có nhân lực phù hợp không, và có UAV đủ điều kiện kỹ thuật/vận hành không?

Khi assessment đạt `READY`, MF02 mới được phép dùng assessment đó để tạo mission.

### 2.2. Điều chỉnh so với flow trước

Flow trước có nguy cơ trùng lặp: MF01 chọn Region/Line/Towers rồi MF02 lại chọn Region/Line/Towers từ đầu.

**Quyết định v2.0:**  
- MF01 lưu **Proposed Scope Snapshot**.
- MF02 **load lại scope từ assessment để review/confirm**, không bắt Manager chọn lại từ đầu.
- Nếu Manager thay đổi scope/time materially ở MF02, assessment phải được **revalidate/re-assess**.

### 2.3. Ranh giới trách nhiệm actor

- **Mission Manager**: tạo/khởi động assessment, xác định proposed scope và planned window.
- **Drone Technician / Technical Drone Team**: chỉ chịu trách nhiệm technical inspection của UAV.
- **Backend/System**: đánh giá scope, personnel availability/eligibility, drone availability và tổng hợp readiness.
- **Inspector/Pilot**: là candidate resource trong MF01, chưa phải người được assign mission.
- Technical Drone Team **không quản lý nhân sự hoặc phê duyệt site** nếu không có permission tương ứng.

### 2.4. Source-of-truth

- Site feasibility trong P0 chỉ dựa trên **GIS data, management scope, configured operational constraints và manual confirmation nếu cần**.
- Không tuyên bố hệ thống tự xác minh đầy đủ airspace/legal/weather realtime nếu chưa có integration.
- Flight Controller integration chỉ **đọc/nhận dữ liệu kỹ thuật phục vụ readiness**; không biến MF01 thành autonomous flight-control module.

## 4. Happy Path

```text
1. Manager starts Pre-Mission Assessment
        ↓
2. Define Proposed Scope + Planned Time Window
        ↓
3. Validate Authorization + Management Scope
        ↓
4. Evaluate Site / Operational Feasibility
        ↓
5. Find Eligible & Available Personnel Candidates
        ↓
6. Find Operationally Available UAV Candidates
        ↓
7. Validate Latest Drone Technical Inspection
        ↓
   ┌───────────────────────────────┐
   │ Valid technical inspection?   │
   └───────────────┬───────────────┘
               Yes │ No
                   │  ↓
                   │ Technical Team runs inspection
                   │  ↓
                   │ Read FC / Sensor / Battery /
                   │ Motor-ESC / Telemetry / Safety
                   │  ↓
                   │ Evaluate Technical Health
                   └───────────────┐
                                   ↓
8. Evaluate Overall Readiness
        ↓
9. Review Assessment Result
        ↓
10. READY → available for MF02
```

Re-assessment:

```text
NOT_READY / INCOMPLETE
        ↓
Resolve issue / repair / update scope / update time
        ↓
Re-evaluate
```

## 5. State Model

### 5.1. PreMissionAssessmentStatus

```text
DRAFT
  ↓
EVALUATING
  ├── READY
  ├── NOT_READY
  └── INCOMPLETE

READY
  ├── CONSUMED     # MF02 successfully created mission
  ├── EXPIRED
  └── CANCELLED

NOT_READY / INCOMPLETE
  └── EVALUATING   # re-assessment
```

### 5.2. DroneTechnicalInspectionStatus

```text
PENDING → IN_PROGRESS → PASSED
                     ├→ FAILED
                     └→ INCOMPLETE
```

### 5.3. Drone status separation

**Không dùng một enum duy nhất để trộn `READY`, `AVAILABLE`, `MAINTENANCE`, `WARNING`.**

Recommended:

```text
OperationalStatus:
- AVAILABLE
- RESERVED
- IN_USE
- MAINTENANCE
- UNAVAILABLE
- LOST

TechnicalHealth:
- UNKNOWN
- HEALTHY
- WARNING
- CRITICAL
```

`MissionEligible` là **computed policy result**, không phải trạng thái vật lý độc lập:

```text
MissionEligible =
    OperationalStatus == AVAILABLE
    && LatestTechnicalInspection is valid
    && TechnicalHealth allowed by mission policy
```

## 6. Validation

- **V01 Authentication:** user phải authenticated.
- **V02 Assessment Permission:** user phải có permission tạo/đánh giá pre-mission assessment.
- **V03 Management Scope:** proposed scope phải nằm trong Manager's authorized scope.
- **V04 Proposed Time Window:** `plannedEndTime > plannedStartTime`.
- **V05 Time Window Not Obsolete:** planned window không được hoàn toàn nằm trong quá khứ.
- **V06 Asset Existence:** Region/Line/Tower/Asset phải tồn tại.
- **V07 GIS Geometry:** nếu có polygon thì geometry hợp lệ, đúng SRID, không self-intersect.
- **V08 Site Feasibility:** mandatory configured site constraints phải pass.
- **V09 Personnel Role:** candidate phải có operational role phù hợp.
- **V10 Personnel Availability:** candidate không có active conflict tại planned window.
- **V11 Personnel Eligibility:** qualification/certification nếu hệ thống quản lý phải còn hiệu lực.
- **V12 Drone Exists:** UAV phải tồn tại và active trong fleet.
- **V13 Drone Operational Availability:** UAV không ở `RESERVED`, `IN_USE`, `MAINTENANCE`, `UNAVAILABLE`, `LOST` tại thời điểm đánh giá.
- **V14 Technical Inspection Presence:** UAV candidate phải có latest completed inspection.
- **V15 Technical Inspection Freshness:** inspection chưa hết `validUntil`.
- **V16 Technical Health:** health phải thỏa policy của mission.
- **V17 Critical Technical Metrics:** critical subsystem failure làm UAV không eligible.
- **V18 Overall Readiness:** `READY` chỉ khi tất cả mandatory condition pass.
- **V19 Assessment Freshness:** assessment phải có `validUntil`; quá hạn → `EXPIRED`.
- **V20 Concurrency:** stale assessment update phải bị reject bằng optimistic concurrency.

## 7. Business Rules

- **BR01 Pre-Mission Assessment Required:** normal MF02 creation phải reference một assessment `READY`.
- **BR02 Assessment Is Planning, Not Mission:** assessment không được tính là mission thật và không làm tăng mission lifecycle counters.
- **BR03 Scope Snapshot:** proposed scope phải được snapshot để MF02 biết chính xác dữ liệu nào đã được đánh giá.
- **BR04 No Duplicate Scope Selection:** MF02 review/confirm scope từ MF01 thay vì bắt chọn lại từ đầu.
- **BR05 Site Feasibility Boundary:** chỉ đánh giá những constraint hệ thống thực sự có dữ liệu.
- **BR06 Personnel Is Candidate Only:** MF01 chỉ xác định candidate/eligibility; assignment chính thức thuộc MF02.
- **BR07 Drone Is Candidate Only:** MF01 không reserve UAV vĩnh viễn.
- **BR08 Technical Inspection Reusability:** một inspection còn hiệu lực có thể phục vụ nhiều assessment.
- **BR09 Latest Valid Inspection:** eligibility dựa trên latest valid inspection, không dựa vào manual `READY` flag.
- **BR10 Technical Source Traceability:** mỗi inspection phải lưu source type/version (CLI/MSP/telemetry/manual-assisted).
- **BR11 Raw vs Evaluated Data:** raw technical snapshot và evaluated result phải tách logic; không overwrite raw evidence.
- **BR12 Technical Thresholds:** threshold phải lấy từ config/policy có version, không hardcode trong controller.
- **BR13 Assessment Expiry:** READY không có nghĩa là READY vô thời hạn.
- **BR14 Revalidation Required:** thay đổi material scope/time hoặc critical resource state làm assessment cần re-evaluate.
- **BR15 Audit:** create/evaluate/re-evaluate/technical inspection/status transition phải audit.
- **BR16 No Autonomous Flight Control:** MF01 không gửi flight-control command.
- **BR17 No Full Betaflight Clone:** chỉ lưu parameter cần cho readiness.
- **BR18 Backend Authority:** client không tự set assessment `READY`.
- **BR19 Idempotent Evaluation:** retry cùng evaluation request không tạo duplicate active evaluation.
- **BR20 Domain Ownership:** site/personnel/drone rules thuộc service/policy tương ứng, không nhét hết vào MissionController.

## 8. Exception Matrix

| Code | Condition | Handling |
|---|---|---|
| EX01 | Unauthenticated | 401 |
| EX02 | Unauthorized / out-of-scope | 403 |
| EX03 | Invalid proposed scope | 400 |
| EX04 | Invalid GIS geometry | 400 |
| EX05 | Invalid planned window | 400 |
| EX06 | Site not feasible | assessment = `NOT_READY` |
| EX07 | Site data insufficient | assessment = `INCOMPLETE` |
| EX08 | No eligible personnel | assessment = `NOT_READY` |
| EX09 | Personnel conflict | candidate excluded / warning |
| EX10 | No operationally available UAV | assessment = `NOT_READY` |
| EX11 | Technical inspection missing/expired | UAV requires inspection |
| EX12 | FC connection failed | inspection = `INCOMPLETE/FAILED` |
| EX13 | Invalid technical data | inspection = `INCOMPLETE` |
| EX14 | Sensor critical | UAV health = `CRITICAL` |
| EX15 | Battery critical | UAV not eligible / maintenance policy |
| EX16 | Motor/ESC critical | UAV not eligible |
| EX17 | Communication/safety invalid | UAV not eligible |
| EX18 | Resource state changed during evaluation | re-query and re-evaluate |
| EX19 | Stale update | 409 |
| EX20 | DB transaction failure | rollback |
| EX21 | Assessment expired | 409 `ASSESSMENT_EXPIRED` |

# 9. Database Impact Review

## 9.1. Existing tables that should be reused

Based on current mission ERD, keep:

- `Users`
- `Regions`
- `LineSegments`
- `AssetComponents`
- `Drones`
- `InspectionMissions`
- `MissionAssets`
- `MissionAssignments`
- `MissionDrones`
- `Notifications`
- `AuditLogs`

MF01 requires **new planning/readiness persistence**. Do not overload `InspectionMissions` with pre-mission temporary data.

## 9.2. Required new tables

### `PreMissionAssessments`

Recommended fields:

```text
Id UUID PK
CreatedByUserId UUID FK Users
RegionId UUID FK Regions
PlannedStartAt timestamptz NOT NULL
PlannedEndAt timestamptz NOT NULL
Geometry geometry NULL
SiteFeasibilityStatus varchar NOT NULL
Status varchar NOT NULL
ValidUntil timestamptz NULL
EvaluationPolicyVersion varchar NULL
CreatedAt timestamptz NOT NULL
UpdatedAt timestamptz NOT NULL
Version bigint NOT NULL
ConsumedMissionId UUID NULL
```

Constraints:

```text
CHECK (PlannedEndAt > PlannedStartAt)
CHECK (Status IN (...))
CHECK (SiteFeasibilityStatus IN (...))
UNIQUE (ConsumedMissionId) WHERE ConsumedMissionId IS NOT NULL
```

### `PreMissionAssessmentAssets`

```text
Id UUID PK
AssessmentId UUID FK PreMissionAssessments ON DELETE CASCADE
AssetId UUID FK <canonical asset table>
CreatedAt timestamptz NOT NULL
UNIQUE (AssessmentId, AssetId)
```

> Nếu hệ thống chưa có canonical `Asset` base table, không dùng `AssetType + AssetId` polymorphic mà không có FK. Ưu tiên chuẩn hóa asset hierarchy hoặc reference đúng table inspection target hiện hữu.

### `PreMissionAssessmentPersonnel`

```text
Id UUID PK

EligibilityStatus varchar NOT NULL

UNIQUE (AssessmentId, UserId)
```

### `DroneTechnicalInspections`

```text
Id UUID PK
DroneId UUID FK Drones

Status varchar NOT NULL
OverallHealth varchar NOT NULL
```

### `DroneTechnicalMetrics`

Use metric rows only for readiness-related parameters:

```text
Id UUID PK
InspectionId UUID FK DroneTechnicalInspections ON DELETE CASCADE
Subsystem varchar NOT NULL
MetricKey varchar NOT NULL
NumericValue numeric NULL
TextValue text NULL
BoolValue boolean NULL
Unit varchar NULL
Severity varchar NOT NULL
IsRequired boolean NOT NULL
Passed boolean NULL
Metadata jsonb NULL
UNIQUE (InspectionId, Subsystem, MetricKey)
```

Constraint:

```text
CHECK (
  (NumericValue IS NOT NULL)::int +
  (TextValue IS NOT NULL)::int +
  (BoolValue IS NOT NULL)::int <= 1
)
```

## 9.3. Changes to `Drones`

Current ERD only has a general `Status`.

Recommended refactor:

```text
OperationalStatus varchar NOT NULL
TechnicalHealth varchar NOT NULL DEFAULT 'UNKNOWN'
LastTechnicalInspectionId UUID NULL
TechnicalHealthUpdatedAt timestamptz NULL
```

Do not store `READY` as both operational state and technical state.

## 9.4. Optional hardening table: `PreMissionAssessmentChecks`

Useful if site/readiness checks grow:

```text
Id
AssessmentId
CheckType
Status
Severity
ReasonCode
Details jsonb

```

This avoids adding 20 boolean columns later.

# 11. Clean Code / Refactor Guidance

Recommended application/domain services:

```text
PreMissionAssessmentService
SiteFeasibilityPolicy
PersonnelEligibilityPolicy
PersonnelAvailabilityService
DroneAvailabilityService
DroneTechnicalReadinessPolicy
DroneTechnicalInspectionService
IFlightControllerTelemetryAdapter
AssessmentExpiryPolicy
```

Adapters:

```text
IFlightControllerTelemetryAdapter
├── BetaflightCliAdapter
├── BetaflightMspAdapter
└── ManualImportAdapter (fallback/testing)
```

Rules:

- Controller only parses request/auth and delegates.
- No business threshold in controller.
- No direct Betaflight process call inside controller.
- No N+1 candidate queries.
- Use cancellation tokens/timeouts for device integration.
- Persist technical inspection atomically.
- Use optimistic concurrency (`Version` or PostgreSQL/Npgsql concurrency token).
- Audit status transitions.
- Unit test policies independently from adapter.

# 12. Test Checklist

Minimum tests before merge:

- Manager out-of-scope cannot assess assets.
- invalid polygon rejected.
- invalid time range rejected.
- personnel schedule conflict excluded.
- unavailable drone excluded.
- expired technical inspection forces reinspection.
- CRITICAL technical metric prevents eligibility.
- WARNING policy behaves according to configured policy.
- assessment READY only when mandatory checks pass.
- READY assessment expires correctly.
- concurrent re-evaluation does not corrupt status.
- raw technical snapshot preserved.
- retry evaluation is idempotent.
- no mission row is created by MF01.

---

# 13. Definition of Done

MF01 v2.0 is done when:

1. Assessment is a separate aggregate from Mission.
2. Scope/time/site/personnel/drone readiness are validated.
3. Drone technical readiness has auditable inspection history.
4. `READY` assessment has explicit expiry.
5. MF02 can consume the assessment without re-selecting scope from scratch.
6. RBAC/scope checks run server-side.
7. Concurrency, idempotency and transaction behavior are tested.
8. No autonomous flight-control behavior is introduced.
